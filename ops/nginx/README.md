# Production nginx config — tracked copy

`cyprusvipestates.conf` is a **read-only mirror** of the live file at
`/etc/nginx/sites-enabled/cyprusvipestates` on the production VPS
(`root@72.60.89.239`). It is not deployed from here automatically — nginx
config changes are made by hand on the VPS, then the updated file is copied
back into this directory so it's never an invisible, untracked layer again
(see the incident this fixes, below).

## Why this exists

2026-07-19: an EN-migration redirect fix was built and deployed entirely at
the Next.js `middleware.ts` level, tested and confirmed correct in local dev
— then found to have **no effect in production**, because nginx already has
its own blanket `/en/` → root rewrite (`location ^~ /en/`) that intercepts
every request before it ever reaches the app. That rule predates this
incident, lived only on the VPS, and appears in no repo, doc, or commit
anywhere — so nobody researching or changing `/en/` routing behavior had any
way to know it existed short of SSHing in and reading `/etc/nginx/`. This
directory + the note in `DEPLOYMENT.md` exist so that never happens again.

## Keeping this in sync

There is currently no automation enforcing that this file matches the live
one — if you edit nginx directly on the VPS, **copy the file back here in
the same session**:

```bash
scp -i ~/.ssh/cvp_vps root@72.60.89.239:/etc/nginx/sites-enabled/cyprusvipestates ops/nginx/cyprusvipestates.conf
git add ops/nginx/cyprusvipestates.conf
git commit -m "ops/nginx: sync after <describe the live change>"
```

Also take a timestamped on-VPS backup before any edit (independent of git,
in case you need to roll back without a deploy):

```bash
ssh -i ~/.ssh/cvp_vps root@72.60.89.239 "mkdir -p /root/nginx-backups && cp /etc/nginx/sites-enabled/cyprusvipestates /root/nginx-backups/cyprusvipestates.conf.\$(date -u +%Y%m%d_%H%M%S)"
```

Always `nginx -t` on the VPS before reloading, and `systemctl reload nginx`
(never `restart`) to avoid dropping in-flight connections.

## Snippets

`snippets/` mirrors the `/etc/nginx/snippets/` files the site config includes
(same copy-back rule as above):

- `cvp_proxy.conf` — the proxy block for every app location; 60 s timeouts.
- `cvp_proxy_admin.conf` — the same block for `/admin` only, with 300 s
  send/read timeouts (2026-09-26). The five-language Claude description (and
  other admin server actions) can run past 60 s; nginx then answered 504 and
  the admin button spun forever. The public site keeps 60 s.

Both snippets blank the client's `x-middleware-subrequest` header
(CVE-2025-29927: on Next.js < 14.2.25 that header makes the app skip its
middleware — the gated-locale 404, the merged/retired redirects and any host
routing). The app is on 14.2.35 since 2026-10-18, so this is defence in depth.

## Partner portal vhost (template, not live yet)

`partner.cyprusvipestates.conf` is the vhost for `partner.cyprusvipestates.com`
(2026-10-18). Unlike `cyprusvipestates.conf` it is **not** a mirror of a live
file: the operator applies it by hand after the DNS A record exists and the
certificate has been issued with certbot (steps in the file header). It is an
allowlist — portal pages plus `/_next/`, `/crm/fonts/` and the icons are
proxied; API, admin, CRM, booking/presentation links, previews, uploads and
SEO files answer 404. Once it is live, copy it back here like the main vhost.
The main vhost answers 404 for `/partner-portal` so the internal segment is
never reachable on cyprusvipestates.com.

## The `/en/` chain map (2026-10-23)

nginx strips every `/en` prefix with a generic rule, and the app then redirects a second time when the unprefixed URL
is a retired project slug or a `/preview-project/<slug>` URL (`301 -> /projects/old -> 308 -> /projects/new`). The map
`cvp_en_final` (top of `cyprusvipestates.conf`, between the `BEGIN/END cvp_en_final` markers) sends the known chain
starts straight to the final page, via one `if ($cvp_en_final) { return 301 $cvp_en_final; }` before `location = /en`.

Regenerate it when legacy redirects change (new archived project, renamed slug):

```bash
node scripts/gen-nginx-en-chain-map.cjs ops/nginx/cyprusvipestates.conf   # needs the DB tunnel on 5433
```

then apply it by hand like any nginx change above (backup, copy, `nginx -t`, `systemctl reload nginx`). A slug that is
not in the map still works, it only costs the extra hop. The live file also carries a WhatsApp-webhook `location`
that the mirror lacked before this sync.
