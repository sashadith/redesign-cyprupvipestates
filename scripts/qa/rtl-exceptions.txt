# RTL physical-property count exceptions (scripts/qa/rtl-physical-count.mjs).
#
# Format: one exception per line —
#   path :: substring
# A line in `path` (matched as a suffix of the scanned file's repo-relative
# path, e.g. "tokens.css" or "src/app/preview-home/tokens.css") that contains
# `substring` is excluded from the physical-property count.
#
# Intended use: decorative atmosphere elements (::before/::after "blobs")
# that are deliberately left physical (they're visual noise, not layout, and
# mirroring them buys nothing — see the plan's Global Constraints), plus any
# other line a human has reviewed and decided should stay physical. Every
# entry should be added deliberately, with a reason a reviewer can check
# against the plan — never used to silence the gate without also fixing or
# reviewing the underlying declaration.
#
# Populated during Task 3 (hot-core manual CSS fixes). Grouped by file below.
# Two recurring categories account for most entries:
#   (a) decorative "cloud"/blob pseudo-elements (atmospheric background glow) —
#       purely visual noise, not layout; mirroring them buys nothing (see the
#       plan's Global Constraints) — left physical.
#   (b) `transform: translateX(...)` — the physical-count tool flags every
#       literal "translateX(" regardless of context. A CSS transform's pixel
#       math is unaffected by `direction`/logical properties, so there is no
#       "logical" form of translateX to convert to. Each site was reviewed:
#       centering transforms (paired with a now-`inset-inline-start: 50%`
#       anchor) are symmetric and direction-agnostic, kept physical; decorative
#       sheens/nudges are cosmetic flourishes with no reading-direction
#       meaning, kept physical; a few genuine hover "nudge toward next"
#       affordances (icon slides right on hover) got a `[dir="rtl"]` mirror
#       override placed right next to them — that override is ALSO a
#       translateX() literal and so is ALSO flagged and ALSO listed here,
#       even though it IS the RTL fix.
